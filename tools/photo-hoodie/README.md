# 실사 사진 기반 아디다스 집업 에셋 빌드

`assets/adidas-kc9315.glb`는 무신사 실물 사진(정·후면 플랫레이, 소매·지퍼·후드 클로즈업)에서
직접 만든 에셋입니다. 앱은 이 파일을 `GLTFLoader`로 읽어 옷의 표면으로 쓰고,
핏·사이즈·보행 변형은 기존 실측 패턴(`sample-garment.mjs` + `hoodie-fit.mjs`)이 계산합니다.

## 파이프라인

    dump_pieces.py  실제 패턴 빌더를 헤드리스(QuickJS)로 돌려 조각별 정점/인덱스를 뽑는다
    build_atlas.py  사진을 조각별 UV 공간(몸판·소매·후드·지퍼)에 구워 아틀라스를 만든다
    glb.py          메시 + 텍스처를 하나의 바이너리 glTF 2.0으로 묶는다

## 실행

    python3 tools/photo-hoodie/dump_pieces.py
    python3 tools/photo-hoodie/build_atlas.py
    python3 tools/photo-hoodie/glb.py

중간 산출물은 `.devtest/photo-hoodie/`에 남습니다(저장소에는 올리지 않음).

## 아틀라스 규약

한 장의 아틀라스가 한 면의 360도를 담습니다. u는 각도가 아니라 **호 길이**입니다.
플랫레이는 옷을 눌러 편 사진이라, 사진에서의 가로 거리가 곧 옷 표면을 따라 잰 거리이기
때문입니다.

    body.png    u 0.00 정면 중심 · 0.25 옆선 · 0.50 등 중심 · 0.75 반대 옆선
                v 0 목(어깨선) → 1 밑단. 밑단 시보리까지 이 한 장에 들어갑니다.
    sleeve.png  u 0 바깥선 · 0.5 겨드랑이 · 1 다시 바깥선. 앞반은 정면 사진,
                뒤반은 후면 사진에서 옵니다. 시보리 소맷단도 이 한 장에 들어갑니다.
    hood.png    후면 사진의 후드(중심 이음선 포함)를 평면 투영.
    zip.png     지퍼 클로즈업의 이빨과 테이프. 지퍼 테이프 천은 단색 재질이고
                이빨(코일)만 이 사진을 입습니다.

행은 사진의 같은 축척으로 놓습니다. 축척은 총장 62 cm(어깨선→밑단)와
소매 58 cm(어깨 이음선→소맷단)에서 잡았습니다(`CX`, `TOP`, `PXPCM`).

사진에서 옷이 없는 자리(소매와 몸판 사이의 배경, 겨드랑이 아래 접힌 부분)는
천의 중간 색으로 채웁니다. 흰 배경이 옷에 구워지면 그대로 회색 얼룩이 됩니다.

## 조명을 나눈 알베도

상품 사진은 스튜디오 조명 아래 찍혀 있어 같은 검정 면이 가슴에서 밝고 밑단에서
어둡고, 윗몸에는 넓은 광택이 흐릅니다. 그대로 구우면 한 가지 검정 옷이 3D에서
회색 두 톤으로 갈라집니다. `flatten`이 **검은 천 픽셀만으로 만든 저주파 조도장**을
나눠 없애고 니트·봉제선·스티치(고주파)는 남깁니다. 세 조각(몸판·소매·후드)이 같은
알베도로 구워지고, 음영은 three.js 조명이 만듭니다.

`glb.py`의 재질은 이 알베도에 빛을 더하지 않습니다. `baseColorFactor`는 1 근처
(0.62 — 이 씬의 밝기에 맞춘 톤 보정)이고, `KHR_materials_sheen`은 쓰지 않으며,
거칠기는 0.86~0.99의 무광입니다. (예전 값 1.9는 크림 테이프와 트레포일을 흰색으로
잘라내고 검정을 회색으로 들어올렸고, sheen은 가슴에 회색 광택을 깔았습니다.)

## 소매 테이프는 사진이 아니라 기하로

플랫레이의 소매는 비스듬하고 실루엣이 배경과 테이프 사이를 오가서, 줄 단위로
따라가면 세 줄이 조여지고 물결칩니다. 테이프는 바깥 접힘에서 잰 거리(1.3·3.2·5.1 cm,
폭 0.95 cm)가 일정한 평행 테이프이므로, 그 거리를 **패턴 단면 둘레로 나눈 호 위치**에
그립니다. 아틀라스 u가 곧 호 길이/둘레라서 3D에서도 곧게 내려갑니다. 소맷단이
봉제되는 v<0.90에서 끝나고, 뒤판은 민무늬입니다(사진과 같습니다).

## 한 벌뿐인 후드

`KC9315`는 사진 에셋이 유일한 후드입니다. 실측 패턴은 크기·보행 변형을 계산할 뿐,
솔리드 색으로 그린 후드(모델링한 포켓·스트라이프 테이프·자수·스티치)는 이 상품에
짓지 않습니다. 사진 에셋이 도착해야 옷이 나타나고, 아직 없으면 옷을 감춥니다.
모델·사이즈를 바꿔 룩을 새로 만들어도 에셋을 함께 넘깁니다.

## 캐시와 버전

`photo-hoodie.mjs`의 `ASSET_VERSION`은 GLB를 다시 구울 때 함께 올립니다
(현재 `2026-11-23i`). GitHub Pages가
파일을 10분간 캐시하므로, 버전을 올리지 않으면 새 원단 대신 예전 파일이 로드됩니다.

스크립트도 같은 이유로 빌드 버전을 붙입니다. 지금은 모든 로컬 모듈 import가 같은
문자열(`?v=...`)을 달고 있습니다. 이 모듈들을 고쳐 배포할 때는 **모든 파일의 문자열을
함께 올려야** 하며, 같은 URL로 두 번 배포하면 브라우저가 예전 스크립트를 계속 씁니다.

`document.documentElement.dataset.hoodie`에 마지막 적용 상태가 남습니다: `loading`,
`worn 20`(조각 수), `failed ...`. 브라우저에서 `document.documentElement.dataset.hoodie`로
확인합니다. `window.__selfit.top`은 조각별 UV·재질·텍스처 크기를 돌려줍니다.
